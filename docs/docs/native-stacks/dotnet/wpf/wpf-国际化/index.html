WPF 国际化

本文将介绍如何通过添加资源文件（.resx）的方式实现 WPF 应用程序的国际化（internationalization, i18n）。

BCP 47 语言标签​

语言标签用于标识世界上的自然语言，其由以下几个部分组成：

language-extlang-script-region-variant-extension-privateuse
主要语言-扩展语言-文字-地区-变体-扩展-私有

我们主要用到的是 language-region 或 language-script-region 这样的形式。例如：zh-CN（中文，中国大陆）、zh-Hans（中文，简体中文）、en-US（英文，美国）。

按照标准，language 应为 2 位小写字母；script 应为 4 位字母，首字母大写；region 应为 2 位大写字母。下面给资源文件命名时千万注意。

添加资源文件​

在“新建项”中选择“资源文件”即可（确认后缀名为 .resx）。建议使用以下文件结构：

[ProjectName]
├── Res/
|   ├── Lang.resx        # 默认语言
|   └── Lang.zh-CN.resx  # 其他支持的语言
...

要支持其他语言，请按照 Lang.[语言标签].resx 的方式命名，这样 IDE 应该会自动识别，编辑起来比较方便：

提示

建议不要通过在 IDE 中复制 Lang.resx 并粘贴的方式创建 Lang.zh-CN.resx，因为这样会创建一个无用的 Lang.zh-CN.Designer.cs。

资源加载逻辑​

如果你添加了 zh-CN 的本地化，你会在生成目录下发现一个 zh-CN/ 文件夹：

zh-CN/
└── [ProjectName].resources.dll

如果你添加了别的语言，道理类似。程序开始运行时，会尝试寻找与系统语言匹配的 .dll。如果找不到，将使用默认的语言。对于我们的 .resx，就是会先寻找匹配的 Lang.[语言标签].resx，如果找不到，将使用 Lang.resx 中的字符串（默认）。笔者建议将默认语言设为英文，这样有更好的国际化效果。

在 Xaml 中使用​

先添加命名空间：

xmlns:loc="clr-namespace:[YourProject].Res"

然后按静态资源引用，比如：

<TextBlock Text="{x:Static loc:Lang.Main_Tip}"/>

这里可以用自动补全，非常方便（需要先生成一次）：

在 C# 中使用​

在 C# 使用更直观。创建 Lang.resx 时，IDE 便会自动生成一个 Lang.Designer.cs，其中就包括一个 Lang 类的定义。我们可以通过访问这个 Lang 类来访问 .resx 中的字符串，比如：

using [ProjectName].Res; // 这样更方便

var tip = Lang.Main_Tip;
