# 关于工具的思考：极客思维 vs 妥协思维

### 副标题：AI 时代，每个需求都值得满足吗？

<br/>

“极客”（geek）原本在美国俚语里是个贬义词，意为“闷蛋、土包子”，但现在更多指“对某领域极感兴趣且知之甚多的人”。当代语境下的极客，往往与科技、互联网深度绑定，甚至带有一种“登峰造极”的褒义色彩。

## 何为极客思维

{/* truncate */}

在笔者看来，极客的一个关键特征就是“极致”。为了这种极致，他们不惜投入大量时间精力。他们所操的这种观念，笔者就称为“极客思维”。如果要细细推究起来，拥有极客思维的人其实不一定是极客（要称为极客，似乎还要有一定成就、地位才行）。本文想探讨的是这种**追求极致**的精神，而非极客本身。

笔者是这样理解极客思维的：譬如一般人发现手机存了太多照片，空间不足了，怎么办呢？通常的想法是：把这些照片转移到其他介质中，比如拷到电脑上。但是电脑不能随身带在身边[^1]，翻看照片不方便，怎么办呢？现在各种手机都推出了“云存储”功能，事实上厂商还恨不得你多用呢。市面上还有各种网盘，也提供相册备份/上云功能。再者，也可以上传到 IM 群聊的相册里。这些就是常见的解决方案了。

但这些方案并非是完美的。比如上述的种种云服务功能，虽说免费，但要忍受广告。如果不充 VIP，还要忍受下载限速。对于极客来说，或许有另一条路：架设一台 NAS，专门用来存储、备份个人数据；再通过内网穿透开放到公网。或者干脆购买云服务商的 NAS 服务。一言以蔽之，常人想到的是 C 端（Client）的方案，而极客可能想到的是 B 端（Business）的处理方法。即“**自己打造工具**”。

对于极客思维者[^2]来说，他们愿意折腾这些技术，花费时间精力，乐在其中。

> 百度百科：
> 极客对这个世界的影响，不仅局限在物质层面，崇尚科技、自由和创造力的极客精神正越来越成为这个时代新的意识形态。……有些高级 Geek 则以编写共享软件为乐事。

## 极客风潮

自己编程造工具、建立个人网站/博客、搭建自己的服务器、本地/私有化部署 LLM……这些事情过去似乎“独属于计算机生”的专利，门槛因 AI 的出现而越来越低。近年 Agents 技术逐渐成熟，Vibe Coder 越来越多，越来越多的人也加入了这场极客风潮。

> 笔者有一种模糊的感觉，未经考证，就是网上关于“如何从 0 开始搭建自己的博客”、“一行代码不写，我打造了xxx”之类的内容，热度一直很高。人们喜欢看到这些行为，很多爱好科技之人也开始动手尝试——尽管不是科班出身。没错，AI 之出现，让“极客”这个词距离让众人更近了一些。

### 人人都能造工具

AI 赋予了普通人像极客一样的“科技水平”，一个笔者认为**最重要**的影响就是降低了工具的制作门槛。比如普通的高中生、初中生，或者与计算机专业不相干的插画师、摄影师、编曲师，或者中小型自媒体博主，都能利用 Vibe Coding 打造自己的工具。

这些 AI 加持下打造的工具如同雨后春笋，层出不穷。当然，也许有不少人只是想蹭个 AI 的热度，但是工具的制作门槛确实大大降低了。过去要造一个工具，需要同时掌握前端和后端技术（也就是全栈），还需要具备程序设计、编码、排障、运维各方面的能力。现在有了 Claude Code、Codex 之类的 Agents，只需要写写提示词就行了。人人在 AI 的借助下都能变身“极客”。

### 人人都能造「轮子」

计算机界有一句话叫作：**不要重复造轮子**。

意思就是，如果一个问题已经有现成的解决方案，就尽量采用现成的，自己造是下策。比如你要做服务器，大多数人都会选择使用 Nginx，而极少人会选择从套接字开始手搓。背后的哲学便是：造轮子的时间远大于用现有的轮子，且你自己造的轮子未必有现成的好。这里笔者想用轮子指代工作、生活中的各种辅助工具。

然而 AI 的出现，使这条“法则”动摇了。

![](assets/2026-08-28-02.webp)

“造上瘾了”

人们解决轮子问题的思路，从过去“挑一个好用的”转变到了“让 AI 写一个好用的”，越来越接近于上文所说的“极客思维”。就拿 SSH 软件做个例子，过去如果挑不到好用的，就妥协一下，将就选一个用。而现在就可以直接让 AI 生成一个全新的。新“极客”们愿意为这样的的极致追求而投入时间精力。当然，有了 AI 之后，投入的成本大大降低了。

正是成本的降低，使得新造的轮子越来越多。本来可能只是觉得界面不好看，新“极客”们也许就愿意捣鼓 AI 做一个新的。这样小小的愿望，在过去可以被妥协，自己忍忍就得了。而现在我们不妥协的成本降低了，人们看到了第二种选择。

这就是笔者所说的“极客风潮”：AI 的出现，让极客思维者越来越多。他们愿意为了过去看来不痛不痒的小需求，花费精力打造新的工具，也热衷在生活中寻找一切有待优化之处，创造新的解决方案。

### 我的经历

制造工具是快乐的。和写作、绘画等创作不同，创造一个工具软件，是在创造一件会反复使用、反复使你受益、“跑”起来的东西，**成就感**是很强的。

**如果做一件事有成就感，那么你就有继续做下去的动力。**

笔者用 AI 创造的第一款工具是 [Collect](https://github.com/masterLazy/Collect)，这是一个我用来管理美术参考图的工具。参考图管理，自然有现成的软件：付费的 Eagle、免费的 Billfish。笔者想直接用文件名存储标签信息，不依赖额外的数据，这样笔者的素材库就不会和某个特定软件绑定，更省心一点。然而，这样的需求确实比较稀奇（虽然抖抖村推荐这么干），据笔者的调查没有什么软件能做到这样。所以笔者就转向了 AI。

AI 打造的工具令笔者很满意。沉浸于喜悦中的笔者转换了心态：过去是犹豫于要不要向软件厂家妥协，此刻却用着自己所造之物“无所不能”；笔者开始不断给这个软件挑刺，精益求精。后来为了让 AI 能更好地调试前端界面，笔者甚至又让 AI 做了一个 MCP 插件：[ollama-vision-mcp](https://github.com/masterLazy/ollama-vision-mcp)。但后来其实没有帮助太多。

至于笔者造的第三个工具，[Harmonology](https://github.com/masterLazy/Harmonology)，则是笔者之前每次制作和声分析视频都要做 PPT + 动画太麻烦，让 AI 创造的方便工具。

后来 DeepSeek 涨价了，笔者才没有造出第四个项目。

### 妥协的缺失

这几次体验 Agents，笔者虽然确实感受到了成就感，但还感受到了另一点：在享受“无所不能”的成就感的同时，我们的要求越来越高，越来越不会妥协了。越来越容易抓住自己的一点小需求不放，为之投入时间精力。

在这里，或许需要停一停。

笔者在前面提到，现在之所以 AI 制造的工具层出不穷，人人都上手，很大程度上是因为不妥协的成本降低了，人们看到了妥协以外的第二个选择。可问题是：我们真的认真想过，“不妥协”真的比妥协更好吗？或者说，我们因为“不妥协”而获得的一点好处（便利、美观，etc.）真的足以我们付出精力去打造工具吗？

> 造出来的工具真的会经常用么？

笔者了解到一个观点：AI 确实降低了成本，**但也让人容易低估使用 AI 的成本**。

在 AI 出现之前和之后，或许也存在着类似的现象：我们有时低估了制造工具的成本。所谓“妥协”，就是牺牲一些需求。我们或许需要停下来考虑一下：我们妥协所牺牲的，与不妥协所需的成本，孰轻孰重？我们值得付出这么多成本吗？笔者认为，AI 出现之后，甚至出现了为不存在的需求打造工具，或者纯粹为了创造工具而创造需求的现象[^3]。这样是不是有些本末倒置了呢？

> 回到开头的例子：自己架设 NAS 真的优于使用网盘、忍受广告么？或者，我们随时看照片的需求真的非满足不可么？

我们需要适当妥协。妥协不是委屈自己，有些情况下反而是更聪明的办法。我们还要接受一个残酷的现实：即使花费了很多精力折腾 AI，也无法得到真正满意的结果。

——仔细想想，万事都求十全十美，其实是一种奢求，本就不现实。不是所有需求都真的值得满足。

## 尾声

笔者现在的这个小站，构建需要如下步骤：

1. 推送源分支更改
2. 构建 Docusaurus
3. 复制构建产物到构建分支
4. 推送构建分支更改

一年来，笔者构建的方法就是自己手敲 `git add .`，`git commit -m ""`，`yarn build`，并且自己复制。这么一趟大概需要一分钟。最近忽然想到，为什么不写一个程序来自动构建并推送呢？笔者在颅内构想了一下，甚至能写一个程序，只需要输入标题就为我创建一篇新的博客，打开开发服务器，还可以方便地帮我处理插入文件这样的需求。

不过又想想，笔者放弃了。像自动创建并插入之类的需求，为之造一个程序，不太值得，而且也很难做到效果很好。至于自动构建呢？笔者也没有写程序，而是写一个 `bat` 就得了（片段示意）：

```batch
call git add .
call git commit -m "%message%"
call git push --force-with-lease
call yarn build
call robocopy "build" "%buildPath%/docs"
cd "%buildPath%"
call git add .
call git commit -m "%message%"
call git push --force-with-lease
```

没有漂亮的 GUI，只是几行 batch file，很简陋。但它确实能解决问题，并且没有消耗我很多时间来写它。笔者认为，这笔妥协很划算。
